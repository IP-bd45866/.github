<h2>一、动手前的准备清单</h2>
<p>需要的东西不多：一条静态住宅IP及凭据、一台常开的机器、一个独立浏览器配置文件、一个检测页。</p>
<p>先确认凭据形式，是账号密码、IP白名单还是密钥文件，三种对应不同配置界面。</p>
<p>再确认线路协议，SOCKS5 与 HTTP 的配置项不同，问清供应商支持哪一种，别配到一半才发现不通。</p>
<h2>二、拿到凭据先做连通测试</h2>
<p>别直接塞进浏览器，先用命令行测一次，拿到出口地址再往下走，省得在图形界面反复试。</p>
<p>测试时看三件事：能否连通、出口是否与分配一致、延迟是否可接受。</p>
<p>不通就先排查本地网络与凭据，通了再谈分流规则，顺序别颠倒。</p>

<h2>三、本机客户端怎么填</h2>
<p>新建一个代理条目，填入地址、端口、用户名、密码，协议按供应商给的选择，保存后设为该配置专用。</p>
<p>分流选规则或全局。只做店铺运营就选全局，避免部分请求绕过代理导致出口不一致。</p>
<p>填完先点测试，客户端会显示出口IP，与分配表核对，一致再继续。</p>
<h3>全局还是规则</h3>
<p>全局简单可靠，代价是本机其他应用也走这条线，视频和下载会占用带宽。</p>
<p>规则模式灵活，但要维护域名清单，漏一条就可能泄漏，团队协作时容易各配各的。</p>
<h2>四、软路由下发整网</h2>
<p>工位多时逐台配置不可维护。用软路由按设备或端口分流，规则集中一处，改动一次全网生效。</p>
<p>常见做法是按源地址分流：某台机器固定走某条出口，员工换机器就要改规则，所以机器要贴标签。</p>
<p>下发后从终端侧验证，别只看路由表，实际访问一次检测页确认出口正确。</p>
<h2>五、浏览器环境绑定</h2>
<p>给每个店铺建独立配置文件，把代理写进配置文件，而不是依赖系统代理，切换环境就不会串线。</p>
<p>时区与语言跟随出口城市设置，美国西部用太平洋时区，东部用东部时区，语言保持与店铺站点一致。</p>
<p>用环境管理工具时，把配置文件、代理、账号放在同一条目里，启动一起加载，减少手工步骤。</p>
<h2>六、验证与压测</h2>
<p>验证分两层：一层是身份，出口、DNS、时区、指纹是否自洽；一层是稳定，能不能长时间不断。</p>
<p>稳定性测试至少挂两小时，记录断线次数与延迟波动，晚高峰再测一轮，两时段都稳才算过关。</p>
<p>压测别用生产账号，拿测试环境跑，避免在真实店铺留下异常记录。</p>
<h3>断线重连要不要开</h3>
<p>自动重连能减少中断，但重连后出口可能变化，如果供应商支持会话保持，建议开启并锁定同一出口。</p>
<p>不支持会话保持的方案，宁可手动重连，也别让程序在后台悄悄换线。</p>
<h2>七、常见故障怎么查</h2>
<p>连不上先看凭据和端口，再看本地防火墙是否拦截，最后确认供应商侧有没有做IP白名单限制。</p>
<p>能连上但打不开页面，多半是DNS没走代理，把远程解析打开再试。</p>
<p>速度慢先测延迟，延迟正常但吞吐低，通常是带宽被同段其他用户占用，找供应商确认共享情况。</p>

<h2>常见问答</h2>
<h3>必须用软路由吗？</h3>
<p>答：不必。单人或两三人用本机客户端就够，软路由的价值在多工位统一管理和防止员工自行改配置。</p>
<h3>静态住宅IP需要每天重启吗？</h3>
<p>答：不需要。静态线路设计上就是长期在线，频繁重启反而增加断线记录，保持常开更稳。</p>
<h3>配置好后本机还能正常上网吗？</h3>
<p>答：全局模式下所有流量都走代理，速度取决于线路带宽。需要本地网络时可切到规则模式或临时停用配置。</p>
<h3>一条线路能同时给几个浏览器用？</h3>
<p>答：技术上可以，建议不超过五个会话。会话过多会排队，而且同一出口的并发行为更容易显得异常。</p>
